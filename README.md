# StoreFront

Адмін-панель для керування інтернет-магазином: товари, замовлення, аналітика,
підтримка клієнтів. Окремий самостійний сервіс з власною базою даних —
не інтеграція з реальним Shopify, лише його адмінка як референс UX.

Повна схема (архітектура, модель даних, API, флоу процесів) —
[DESIGN.md](DESIGN.md). Це і є Підзавдання 1 з брифу; цей README —
статус Підзавдання 2 (реалізація за нею).

## Поточний статус

Готові Етапи 0-2 (коміти `09ab809` → `058a7f1`). Що вже працює:

- **Інфраструктура.** `postgres` + `backend` + `nginx` у Docker Compose;
  опублікований порт лише один — `80` у nginx, решта тільки `expose`
  всередині docker-мережі.
- **Автентифікація.** `POST /api/auth/login`, `POST /api/auth/logout`,
  `GET /api/auth/me`. JWT у httpOnly-кукі, ролі `ADMIN`/`STAFF`,
  `requireAuth`/`requireRole` middleware.
- **Товари.** Моделі `Product`, `ProductVariant`, `ProductImage`,
  `ProductCustomField`. CRUD для товарів (список з пагінацією, фільтром
  за статусом і пошуком за назвою, створення, деталі, оновлення,
  архівування — soft delete, тільки `ADMIN`), для варіантів (унікальний
  SKU з обробкою конфлікту) і для довільних кастомних полів
  (Shopify-подібні metafields — ключ унікальний у межах товару).
- **Тести.** 36 юніт-тестів (zod-схеми, auth-middleware, контролер
  товарів із замоканим Prisma-клієнтом) — усі проходять.
- **Дефолтний адмін після сіда:** `admin@storefront.dev` / `admin12345`
  (лише для локальної розробки).

Ще не зроблено: адмін-панель (Етап 3) і все, що після неї, — див.
дорожню карту нижче.

## Стек

- **frontend/** — Next.js (App Router) + [Shopify Polaris](https://polaris.shopify.com/) для UI адмінки
- **backend/** — Express + Prisma + PostgreSQL, REST API
- **nginx/** — єдина публічна точка входу; все інше (БД, кеш, бекенд, фронтенд) без опублікованих портів
- **сховище файлів** — S3-сумісне (MinIO локально, Cloudflare R2 у проді) — з Етапу 7

## Розробка

```bash
docker compose up -d --build
docker compose exec backend npm run prisma:seed   # разово: перший ADMIN
```

Все йде через **http://localhost** (nginx, порт 80) — `/api/*` на бекенд,
решта тимчасово теж на бекенд, поки не з'явився фронтенд (Етап 3).
Жоден інший порт назовні не відкритий: Postgres і бекенд доступні лише
всередині docker-мережі. Деталі — у `backend/README.md`.

## Політика портів

Жоден внутрішній сервіс (БД, майбутній Redis-кеш, бекенд, фронтенд)
не публікує порт на хост — тільки `expose` всередині docker-мережі,
підключення по паролю. Єдиний опублікований порт — `80` у nginx.
Це стосується й Redis, коли він з'явиться: за замовчуванням теж без
`ports`, тільки `expose`.
