# StoreFront

Адмін-панель для керування інтернет-магазином: товари, замовлення, аналітика,
підтримка клієнтів. Окремий самостійний сервіс з власною базою даних —
не інтеграція з реальним Shopify, лише його адмінка як референс UX.

Повна схема (архітектура, модель даних, API, флоу процесів) —
[DESIGN.md](DESIGN.md). Це і є Підзавдання 1 з брифу; цей README —
статус Підзавдання 2 (реалізація за нею).

## Поточний статус

Готові Етапи 0-6. Що вже працює:

- **Інфраструктура.** `postgres` + `backend` + `nginx` у Docker Compose;
  опублікований порт лише один — `80` у nginx, решта тільки `expose`
  всередині docker-мережі.
- **Автентифікація.** `POST /api/auth/login`, `POST /api/auth/logout`,
  `GET /api/auth/me`. JWT у httpOnly-кукі, ролі `ADMIN`/`STAFF`,
  `requireAuth`/`requireRole` middleware.
- **Товари.** Моделі `Product`, `ProductVariant`, `ProductImage`,
  `ProductCustomField`. CRUD для товарів (список з пагінацією, фільтром
  за статусом і пошуком за назвою, створення, деталі, оновлення,
  архівування — soft delete, тільки `ADMIN`), для варіантів (унікальний
  SKU з обробкою конфлікту) і для довільних кастомних полів
  (Shopify-подібні metafields — ключ унікальний у межах товару).
- **Замовлення.** Моделі `Customer`, `Order`, `OrderItem`. Список з
  фільтром за статусом, деталі з позиціями й порахованою сумою, зміна
  статусу лише дозволеними переходами (`PENDING → PAID → FULFILLED`,
  `PENDING → CANCELLED`, `PAID → REFUNDED`) — стейт-машина на бекенді,
  фронт лише малює кнопки під те, що дозволено.
- **Підтримка клієнтів.** Моделі `Ticket`, `TicketMessage`. Список з
  фільтром за статусом, деталі з повним листуванням, відповідь
  персоналу (одразу з можливістю закрити тікет тим самим запитом) і
  ручна зміна статусу — на відміну від замовлень, тут статус міняється
  вільно в будь-якому напрямку (`OPEN`/`PENDING_CUSTOMER`/`CLOSED`),
  без таблиці дозволених переходів: діалог підтримки не такий лінійний,
  як оплата замовлення.
- **Аналітика.** `GET /api/analytics/summary`, опційно `?days=N`.
  Виручка (сума позицій оплачених/виконаних замовлень), кількість
  замовлень за період і топ-5 товарів за кількістю проданого —
  рахується в JS із позицій замовлень, без SQL-агрегації чи сирих
  запитів (MVP-обсяг даних цього не виправдовує).
- **Тести.** 61 юніт-тест (zod-схеми, auth-middleware, контролери
  товарів, замовлень, тікетів і аналітики із замоканим Prisma-клієнтом)
  — усі проходять.
- **Дефолтний адмін після сіда:** `admin@storefront.dev` / `admin12345`
  (лише для локальної розробки).
- **Адмінка.** Next.js 16 + shadcn/ui (не Polaris — деталі нижче).
  Логін, навігація, повний цикл товару (список/створення/редагування/
  варіанти/кастомні поля), замовлень (список/деталі/зміна статусу),
  підтримки (список/деталі/відповідь/статус) і дашборд аналітики
  (фільтр періоду, топ-товари) — усе через Server Actions/Components,
  без окремого клієнтського API-шару.

Ще не зроблено: медіа, стабілізація — див. дорожню карту.

## Стек

- **frontend/** — Next.js 16 (App Router) + [shadcn/ui](https://ui.shadcn.com/) для UI адмінки
- **backend/** — Express + Prisma + PostgreSQL, REST API
- **nginx/** — єдина публічна точка входу; все інше (БД, кеш, бекенд, фронтенд) без опублікованих портів
- **сховище файлів** — S3-сумісне (MinIO локально, Cloudflare R2 у проді) — з Етапу 7

**Чому не Polaris, як просив бриф:** `@shopify/polaris` (React) —
офіційно deprecated, Shopify його більше не підтримує. Заміна
("Polaris web components") розрахована на застосунки, вбудовані в
саму адмінку Shopify, а не на окремий сервіс на кшталт нашого —
не підходить за задумом. Деталі — `frontend/README.md`.

## Розробка

```bash
docker compose up -d --build
docker compose exec backend npm run prisma:seed   # разово: перший ADMIN
```

Все йде через **http://localhost** (nginx, порт 80) — `/api/*` на
бекенд, решта на фронтенд. Жоден інший порт назовні не відкритий.
Деталі — у `backend/README.md` і `frontend/README.md`.

## Політика портів

Жоден внутрішній сервіс (БД, майбутній Redis-кеш, бекенд, фронтенд)
не публікує порт на хост — тільки `expose` всередині docker-мережі,
підключення по паролю. Єдиний опублікований порт — `80` у nginx.
Це стосується й Redis, коли він з'явиться: за замовчуванням теж без
`ports`, тільки `expose`.
