# frontend

Next.js 16 (App Router) + shadcn/ui. Адмін-панель StoreFront.

## Чому shadcn/ui, а не Polaris

Бриф просив Polaris, але `@shopify/polaris` (React-пакет) виявився
офіційно deprecated — Shopify більше його не підтримує, лише архівна
документація. Заміна ("Polaris web components") розрахована на
застосунки, вбудовані в саму адмінку Shopify (App Home/App Bridge),
а не на окремий самостійний сервіс на кшталт нашого — тож не підходить
за задумом. Замість цього — shadcn/ui: не npm-залежність, а джерельний
код компонентів у самому репозиторії (`src/components/ui/`), нічого
не "зникне" з-під ніг.

**Реальна несподіванка:** поточний стиль shadcn ("base-nova") збирає
компоненти на [Base UI](https://base-ui.com/), не на Radix. Композиція
інша: замість `<Button asChild><Link .../></Button>` тут
`<Button render={<Link ... />} nativeButton={false} />`.

## Стек і конвенції

- **Next.js 16.3.5**, App Router, TypeScript, Turbopack (дефолт для `next dev`).
- **React 18**, не 19 — `@shopify/polaris` уже прибрано, але React лишили
  на 18, бо саме на ньому усе перевірено; піднімати versiю окремо не було приводу.
- **Tailwind CSS v4** (CSS-first конфіг, без `tailwind.config.js`) + shadcn/ui.
- **Zustand** — під'єднано, ще не використовується: перших клієнтських
  UI-станів (bulk-select, чернетка форми) поки що не з'явилось.
- `proxy.ts` (у 16-й версії Middleware перейменували на Proxy) —
  оптимістична перевірка сесії за наявністю куки `token`, без звернень
  до бекенду. Справжню валідність токена перевіряє сам бекенд;
  прострочений/підроблений токен ловить `(admin)/layout.tsx` (401 → редірект).

## Як дані доходять до сторінок

Два різні шляхи, і обидва навмисні:

- **Браузер → nginx → backend.** Клієнтський код (форма логіну,
  logout) б'є у відносний `/api/...` — той самий origin, кука
  прикладається сама, CORS ні до чого.
- **Сервер (Server Components) → backend напряму.** `src/lib/api.ts`
  ходить у `BACKEND_INTERNAL_URL` (`http://backend:5051`), в обхід
  nginx — швидше, і це вже інший процес, тож кука форвардиться вручну
  (`cookies().toString()` у заголовок `Cookie`).

## Локальний запуск

Той самий підхід, що й у backend — контейнер, hot-reload через volume,
нічого не запускається напряму на хості:

```bash
cd ..                      # корінь storefront/
docker compose up -d --build
```

Усе через **http://localhost** (nginx, порт 80) — не `:3000`, він не
опублікований.

## Ендпоінти адмінки

| Шлях                 | Опис                                          |
| --------------------- | ---------------------------------------------- |
| `/login`              | Форма входу                                    |
| `/products`           | Список товарів — пагінація, пошук, фільтр статусу |
| `/products/:id`       | Картка товару — варіанти, кастомні поля (поки без редагування) |

`/products/new` і редагування товару — наступний крок; зараз сторінка
лише показує дані.
